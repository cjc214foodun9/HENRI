1. Your premise, with one correction that changes the design

You said the missing ground truth should be found in Zone C. I built the smallest real version of that and measured it. The correction: Zone C supplies facts; facts are not structure. A fact store fixes retrieval of remembered content. It does not by itself raise the generative ceiling of a program-synthesis task.

That distinction is not philosophy — it is measured. A flat nearest-neighbour engram store over waves scores 0.1667; the pre-registered bar is 0.1671. It clears the unigram floor (0.1171) and beats its own control 2.25×, but it does not clear the bar. So a Zone C store is a real mechanism and not, by itself, the answer.

3. The finding that decides the program order

The text→wave map had no differentiable path at all

Step 1 could not be done as written. Unfreezing the ingress would have created a dead flag: the optimizer would hold the parameters and the gradient would be exactly zero. Measured, three independent ways:

  • wave_of is wrapped in torch.no_grad().
  • Calling encode_text() directly still returns requires_grad=False.
  • The path severs at argmax(routes) → python int, at self.angle[tok] (a frozen buffer), and at torch.polar(torch.tensor(1.0), phase), whose magnitude is a fresh constant. The accumulator is a new zeros tensor.

Measured separately: torch.polar is differentiable in the phase, and Parameter[int_index] does return a grad-carrying tensor. So zone_a.phase_residual — an exact-zeros phase offset indexed by token id — is the minimum construction that makes the ingress trainable. It initializes to zeros, so every committed receipt still reproduces byte-for-byte.

Step 1 is necessary and not sufficient

With the ingress trainable and reaching gradient, M4-G1 held-out accuracy is 0.0357 / 0.0446 / 0.0893 across three pinned seeds — every one below the unigram floor of 0.1171. The margin ratio is 1.143 (above its own shuffled control) but the absolute bar is not met.

Reading: with 48 training examples the unfrozen ingress memorizes too. Reachability is solved; transfer is not. No amount of flag-tuning changes that number.

5. Your three questions, answered from measurement

What should the ground-truth engrams be, at the data level?

engram := (Psi_spec, Psi_trace) — the input wave as key, its executed-and-verified output wave as value, stored co-resident, not bound. This is measured, not asserted: HRR binding scores 0.0463 against co-storage's 0.1667. Binding adds cost and removes signal at this data level. Each engram also carries provenance — a source digest and the verification that produced it.

Where should the raw data come from?

From any system where input→output is verifiable by execution. For M4 that is the program executor, which yields exact traces for free and without limit. This generalizes: SQL engines, simulators, type checkers — anywhere a result can be checked by running it. Ground truth is executed, not annotated. One hard rule: never seed the store with benchmark gold answers, or every later score is void.

Is training-as-test-time-scanning a viable route?

As retrieval, yes — measured. The E1 arm beats its control 2.25× and lifts coverage@5 by 0.1785 over a shuffled store. It is the best non-parametric performer measured on this task, ahead of the 414M readout (0.0000) and level with ridge (0.1339).
As learning, not yet. Sequential registration fails its own control. The mechanism is worth building; the claim that it improves with experience is not supported by this experiment.

6. Why the program order inverts

Every arm that trains memorizes 48 examples and generalizes to zero: the 414M readout (0.0000), the learnable ingress (0.0357 / 0.0446 / 0.0893), the small MLP (below its own control). Every arm that retrieves generalizes a little: k-NN (0.1389), ridge (0.1339), the engram store (0.1667).

The binding constraint is data volume. Forty-eight examples cannot teach a 414M-parameter model anything transferable, and no mechanism change fixes that. The engram store wins precisely because it does not train.

Next most important decision (ESCALATE — it changes the task definition): scale the corpus before scaling the model. The M4 executor can generate unlimited verified triples. A 10,000-example corpus on the same pinned harness would make every trained arm falsifiable and would settle whether the representation ceiling is data-bound or architecture-bound. It is the cheapest experiment that can change the verdict, and it needs your approval.

8. Defects I found in my own work this turn

  • Dead loop guard. My first patch bound the wave before the training loop, so the guard that rebuilds it never fired — measured max_param_delta 0.0 in fit() while a manual replica of the same code moved 0.0 → 0.048. The replica is what exposed it.
  • Autograd on a python float. The assembler compared float(n) on a grad-carrying tensor — warns and is undefined under autograd. Now float(n.detach()).
  • Vacuous coverage control. My coverage() took a similarity matrix and then closed over the global one, so the real and shuffled arms printed identical numbers. A control that cannot differ from its treatment is vacuous. Fixed by passing the label map.
  • Two HRR shape bugs. A flattened 8192-dim query against a 4096-dim complex wave; then a 48-key bind correlated against 108 queries. Rewritten as a Parseval pairwise complex matmul, which allocates no 3-D tensor.
  • One label I got wrong. I first called the E3 zero a "broken arm." It is zero by construction — no train spec contains a length-3 program — and that is a good control, proving the split has no literal leakage.
